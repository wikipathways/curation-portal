GitHub's authorisation page lists `public_repo` as read and write to all your public repository data, which reads alarmingly for someone signing in to upload one file — and it scared off a real colleague. There is no narrower option: OAuth scopes are account-wide, so `public_repo` is the least the app can ask for and still push a branch (issue #30). Naming it before the redirect is the whole mitigation; the surprise is what does the damage, not the scope. The *why* now lives in the OAuth App's description, which GitHub renders on the consent screen itself, so this only has to stop that screen being a surprise. Two constraints on any rewording.
