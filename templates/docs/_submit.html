1. Sign in with GitHub (top right), then stay on the Submit page with the New pathway tab selected.
  2. Choose your .gpml file. The portal checks it at once, before anything is sent anywhere, and lists what it found right under the file picker. Each finding is marked Blocked, Problem or Worth a look (what the checks are). Only a Blocked finding stops the submission: the file is not a readable pathway, or it has no title or organism. Everything else is advice, and fixing it now saves a round trip with a curator.
  3. Add a note for reviewers if there is something a curator should know: where the pathway comes from, what it covers, open questions. It is optional, and it is shown on the review page and on the pull request.
  4. Press Submit new pathway. The portal files the pathway where the repository expects it, opens the pull request in your name and shows you its number, with a link to Follow the review.

Where your pull request comes from

Most people cannot write to the WikiPathways repository directly, so on your first submission the portal creates your own copy of it on GitHub (a fork) and opens the pull request from there. You do not have to do anything with the fork. Before each submission the portal tries to bring it up to date with the repository. If your fork carries changes of its own that the repository does not have, the portal opens the pull request through its own GitHub account instead, so those changes cannot slip into your submission; you are still named as the author.

Limits

  • One pathway per submission. To submit several, upload them one at a time.
  • To stop runaway retries, one account can open a limited number of pull requests per hour. Uploading a correction to an existing pull request does not count.
