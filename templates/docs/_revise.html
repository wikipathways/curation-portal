When a curator asks for changes, the submission moves to Changes requested. The curator's note is posted on the pull request, so GitHub emails you, and it is shown on the review page. Your submission waits for you; it is back in the curators' queue as soon as you upload a fix.

A new pathway

Open the review from My submissions. Under the checklist there is an Upload a revision box: choose the corrected file (it is checked like any upload) and press Commit onto this pull request. The file replaces the old one on the same pull request; no new one is opened.

An update of a published pathway

Upload the corrected file through the Update existing form with the same WPID. The review page links there with the WPID filled in. It lands on the same pull request.

A pull request opened on GitHub

If you opened the pull request yourself on GitHub (for example from the PathVisio plugin) rather than through this portal, the portal cannot change it for you. Push the corrected GPML to the pull request's branch; the portal reads it again and the review returns to the queue.

Talking to the curator

The review page shows the pull request's conversation. You and the curators can add comments there; they are posted on GitHub under your own name. A comment does not change the state of the review: to answer a change request, upload the fix.
