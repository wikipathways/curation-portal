Every submission has a review page, reached from the queue with Open full review. Submitters see the same page as curators, without the controls only curators may use. From top to bottom:

Status and progress
A banner says which state the submission is in and who it is waiting on (the states). Checked … ago says when the portal last compared the review with GitHub; Refresh updates the card in place without reloading the page. While the repository is processing or publishing, the card refreshes itself. {% if pipeline_mode %}Once a submission is approved, a progress tracker shows how far publication has got (what each stage means), and the rest of the review folds away under Review details, which opens it again.{% endif %}
Automated checks
The portal's checks on the uploaded file (the full list). Where the repository runs the same check itself and has reported back, its answer is shown beside the portal's. A note also appears here when the repository's own processing of the pull request failed.
Database checks
For an update: WikiPathways' own quality report on the version that is published now, before this edit. A problem listed there was already there unless this edit fixes it.
What changed
For an update: how many data nodes were added, removed, re-annotated (same label, different identifier), relabelled or only moved, and whether the title, description, references or ontology tags changed.
The diagram
The pathway drawn by the portal from the uploaded file; for an update, the published version and the new one side by side. How to use it is described below. Under it, once the repository has processed the pull request, a link to the draft page, the pathway's page as it will look on {{ site_host or 'the site' }}.
What the repository generated
The repository's own reading of the file: how many data nodes it annotated and references it resolved, its own render and a link to its workflow run. It appears once that run has finished; the portal's diagram does not depend on it.
Submitter note, description, data nodes, references, ontology tags
What the file contains, as tables. Data nodes without an identifier are marked not annotated; identifiers and references link to their databases.
Curation checklist
The questions a curator answers before approving (the items). Every item starts unanswered. Under an item, Automated check says what the portal or the repository's pipeline found and what it suggests; the curator decides.
Conversation and history
The pull request's comments, from people and from the repository's workflows, with a box to add one; and a record of who did what to the review.

Using the diagram

Drag to move around, and use the toolbar or the keys below to zoom. Hovering over a node shows its name; clicking it opens its properties (type, identifier with a link to the database, group, and the interactions it takes part in) and highlights its neighbours, so you can follow what connects to what. Clicking a line shows its type and the two things it connects. Click an interaction in the properties to jump to it.

  • Zoom with + and −, or with Ctrl (Cmd on a Mac) and the mouse wheel. Pinch on a touch screen. Fit shows the whole pathway again.
  • Fullscreen gives the diagram the whole screen; for an update, both versions go fullscreen together.
  • Search finds nodes by label or identifier (for example AHR, ENSG00000106546 or Ensembl:ENSG00000106546). Press Enter to step through the matches.
  • Legend lists the node, line and group types in this pathway and, for an update, the change colours with their counts.
  • Show unconnected line ends marks every line that ends near a node without being attached to it, which is what the Interactions are connected checklist item asks about.
  • Portal render / Database render switches to the picture the repository's pipeline drew, once it exists. That one is a plain image: no search or properties.

On the queue the diagrams are still pictures until you point at, click or tab into one, which keeps a long queue fast. The full review page is interactive from the start.

Comparing two versions

For an update the two diagrams move together: zoom or pan one and the other follows, and selecting a node selects its counterpart. Changed nodes are coloured and outlined by kind of change, with a badge, so the difference does not rely on colour alone. Previous and Next change step through the changes in reading order. A switch in the legend hides nodes that only moved, since a re-layout can produce many of them.
